# Mount and action movement controls

This change set is on the isolated `codex/mount-action-recovery-20261113-updated` branch. It merges upstream `main` at `4e08e9f7589e4d63f4e2c8f34513f8126b2f9329` with the local gameplay changes and keeps GX EP5.4 separate from the Shaiya2 CORE implementation.

## Behavior

- The world server owns timed skill and mount cast deadlines. A `0x0501` packet cannot clear a pending cast: changed coordinates, vertical changes, and nonzero movement modes are rejected until the deadline. Rejections send a bounded position correction (at most one per 100 ms) and a throttled log entry.
- While a skill cast is pending, the server also blocks new attacks and skills, stops the current auto-attack, and refuses locomotion `0x0506` motions. The client suppresses local movement prediction during a cast and keeps the cast animation when it receives an authoritative position correction.
- On skill release, the server blocks movement, new attacks, new skills, and one-shot motions through a recovery deadline derived from the actual release action ANI. Instant (`ReadyTime=0`) skills receive the same server-owned recovery. The client uses the same generated duration table when it receives a successful skill result, so movement prediction stays aligned with the server.
- The server's existing weapon recovery deadline also rejects movement. The client now holds movement through the matching local attack action and the server-reported attack-speed interval, avoiding repeated rejected movement and visible position snaps.
- The client keeps the camera's right-drag independent from a fixed travel or combat heading. Right-drag can still steer while the player is moving freely.
- Backward movement on a mount uses the native walk animation and preserves the rider's forward heading. Mounted jump uses the matching `Vehicle/ANI/*_jump.ANI` when the mount model provides it; remote mounted characters use the same motion flag.
- A mounted jump does not apply a separate jump arc or `008_jump` action to the rider. This includes skateboards: the character keeps the existing riding/skating clip and position relative to the board, while the vehicle plays its jump ANI and the rider follows its animated seat. The server rejects the standalone rider jump motion while mounted.
- Mount reuse is one timer for equipment bag 0, slot 13. The server starts it when dismounting or replacing the active mount, using the last mounted item's `ReqIg` value. Mounting does not start or reset it, and changing the item in slot 13 does not evade the remaining time. The client shades only that equipment slot and displays the server-provided milliseconds.
- `/mount [seconds]` remains an admin-only, fork-local test command. When unmounted it starts the mount action immediately; the whole-second value is a server-authoritative cast override for that session. `/mount 0` is instant; values such as 5, 7, 9, and 10 exercise longer cast cases. When already mounted, it dismounts. The current upstream has no equivalent GM mount-cast command, so this helper is retained here to test mount timings.
- The merged upstream GM dispatcher provides `/getitem <type> <id> <quantity>`. It grants transactionally, stacks to the item definition's limit, and rejects a grant that cannot fit. Use `/getitem 42 2 1` to provision one leopard mount for local tests. This replaces the older local two-argument helper; see `docs/gm.md` for the complete GM command list.
- The local test branch also relaxes equipment requirements for Type 42 in mount slot 13, so the provisioned mount can be tested with level-1 characters. This is a test-server rule and is not part of the proposed upstream gameplay fixes.
- Right-clicking an equipped inventory item moves it to the first available slot in bags 1–5. Right-clicking an item in a regular bag keeps the existing equip behavior.

## Wire compatibility

GX uses two optional response extensions in this branch: four milliseconds bytes on `0x0216` for mount cooldown, and four seconds bytes on a mount-only `0x0510` cast-start. The GX client decoder tolerates the original shorter packets. These extensions should be reviewed before sending this branch to an upstream server that does not implement them.

## Validation and limits

- `gofmt` and `git diff --check` completed.
- Windows/amd64 builds succeeded with Go 1.27.3; server build used `CGO_ENABLED=0`, client build used LLVM-MinGW x64 with `CGO_ENABLED=1`.
- Automated tests were not run. The binaries were installed to the local GX test packages, and login/world are listening on `127.0.0.1:30800` and `127.0.0.1:30810`; an in-game gameplay pass is still needed.
- Skill release durations are generated by `tools/generate_skill_recovery` from the local client's `Character/Skill.SData`, 16 character action ALT files, and 1,176 referenced ANI clips. It emits numeric timing tables for client and server; no client assets are copied into the server. The source `Skill.SData` SHA-256 is `4f94d2a5b88971936cbbfb5bc9d26c9ea66be1d6d3825a0a08844f55f02da302`; the action/ANI content digest is `f1f983b27914f035efd96447405d74422a78d5e7e668b045448ee65bbf3ef6a8`. The generated table covers all 978 player skill rows (levels 1–3) in the server seed DB; level-100 status rows are excluded. Durations use the maximum matching action clip across weapon variants and character models, rounded up to the 100 ms server tick. This is conservative and can hold some combinations slightly longer than their own clip.
- Mounted jump, the conservative recovery window, cooldown UI, and attack feel still need a visual in-game check. Automated tests were not run.

## Reproducing the Windows build

From the repository root, with the local Go 1.27.3 toolchain and LLVM-MinGW x64 available:

```powershell
$env:GOOS='windows'
$env:GOARCH='amd64'
$env:GOAMD64='v1'
$env:CGO_ENABLED='0'
go build -trimpath -o build/gx_world.exe ./server/cmd/gx_world
```

For the client, set `CGO_ENABLED=1`, set `CC` to `x86_64-w64-mingw32-gcc.exe`, put the LLVM-MinGW `bin` directory on `PATH`, and build `./cmd/shaiya` to `Shaiya GX.exe`.

Regenerate both recovery tables from an extracted client data directory:

```powershell
go run ./tools/generate_skill_recovery `
  -client-data 'T:\path\to\client\data' `
  -out 'server/internal/world/skill_recovery_generated.go' `
  -app-out 'internal/app/skill_recovery_generated.go'
```
